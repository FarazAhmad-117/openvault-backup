# OpenVault Backup Website Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Ship a multi-page, award-level, SEO-ready static marketing site for OpenVault Backup in `website/`, deployable to Vercel, with an always-current download button and honest feature status.

**Architecture:** Astro 5 static site. All facts (name, domain, repo, version, feature statuses) come from three data modules so pages never hard-code them; every page renders through one `Base` layout that emits SEO tags and JSON-LD built by pure, unit-tested helpers. Docs pages are generated from `../docs/guides/*.md` via a content collection. Design follows `docs/plan/12-website.md`.

**Tech Stack:** Astro 5, TypeScript, plain CSS (custom properties) + a little vanilla JS for the hero, Vitest (unit), `@astrojs/sitemap`, linkinator (links), pa11y or axe (a11y), Lighthouse CI. Everything verified in Docker (`node:22`).

**Rules that apply to every task** (from `CLAUDE.md` and `docs/plan/12-website.md`):
- Never hard-code the domain. It comes from `SITE_URL`.
- Never show a feature as **Available** unless it works in a released build. Status lives only in `src/data/features.ts`.
- Public repo: no secrets, no private paths.
- Respect `prefers-reduced-motion`; AA contrast; one `<h1>` per page.
- Commits: the repo is not yet a git repository. If `git init` has been done, commit after each task; otherwise skip the commit step.

**Docker command prefix used below** (run from the repo root, Git Bash):
```bash
WEB="docker run --rm -v \"$(pwd -W):/repo\" -w /repo/website node:22-alpine"
# usage: eval $WEB npm test
```

```ts
export const label = (s: Status) => ({ available: 'Available', 'in-progress': 'In progress', planned: 'Planned' }[s]);
export const countByStatus = (items: { status: Status }[]) =>
```
